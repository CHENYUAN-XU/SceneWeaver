# SceneWeaver 已知限制

## 缓存清理边界（2026-07-19）

- 清理缓存后，应用会按需重新生成媒体派生文件；原素材、数据库、模型及用户选片不受影响。

## 素材库重新连接边界（2026-07-19）

- 移动恢复按“原根目录下相对路径不变”判断，因此能可靠覆盖外接盘盘符变化、根目录搬迁和完整目录移动；如果文件重命名、改了层级或内容替换，下一轮增量扫描会把旧记录离线并按正常规则处理新文件，不会猜测性合并。
- 当前不对跨目录重命名执行内容哈希全盘匹配，避免在大媒体库中产生长时间阻塞和错误关联；源媒体始终不被重命名、移动或删除。
- 已由 `core_smoke` 覆盖本地目录移动；真实外接硬盘拔插、UNC 共享和 GUI 端到端交互仍需继续在用户环境验证。

## 扫描队列边界（2026-07-19）

- 同一素材库只允许一条 pending/running/paused 扫描；若任务因进程中断恢复为 pending，必须等待、取消或完成，不能绕过恢复路径再建并行任务。
- 去重针对扫描任务；缩略图、镜头切分和语义索引等将来的独立后台任务仍需要在各自资源约束下单独调度。

## HTML 联系表边界（2026-07-19）

- HTML 是离线审片清单而非可编辑时间线，也不会复制原始媒体；其中显示的是用户本机绝对路径，分享前应确认路径及备注不含敏感信息。
- 联系表只嵌入已有缓存缩略图，不会为导出而重新处理原媒体；缓存缺失时保留项目元数据与时间范围并显示占位。

## 选片标签边界（2026-07-25）

- 选片标签用于表达当前集合内的剪辑意图（例如“开场”“备选”），不等同素材标签，也不会反向参与素材库的 Must / Should / Must Not 搜索。
- 标签按选片项存储；同一素材加入不同集合或以不同片段加入时可具有不同标签。当前可在单个集合内筛选、全选筛选结果并批量添加标签，但未提供跨集合标签统计或跨集合批量编辑。

## 当前版本限制

- 日期范围优先使用视频/音频容器中由 FFprobe 返回的 RFC 3339 creation_time（含兼容 QuickTime 创建时间），或图片 EXIF 中带相应 OffsetTime 的 DateTimeOriginal、DateTimeDigitized、DateTime。无时区 EXIF、GPS 时间、厂商私有日期和不支持的容器日期尚未解析；它们会明确忽略而不是按本机时区猜测，因此仍不能将所有素材筛选结果理解为精确拍摄日期。

- 日期卡片的格式化使用当前操作系统本地时区，仅展示可用于本地日期范围筛选的时间点；不会显示或推断原始拍摄地时区。

- 相对路径以当前素材库根目录为基准；素材库重新连接后会相对新根目录计算，外部剪辑工程仍需自行处理其项目根目录差异。

- Entity 结果现在展示候选来源，但尚未具备经真实数据集校准的身份置信度或跨 Provider 统一分数；来源说明不应被理解为人脸/角色识别结论。

- 批量打开会调用操作系统关联程序；当前未提供一次性打开数量上限或外部剪辑软件专用拖拽集成，用户应避免一次选择过多文件。

- 首次导入引导已复用现有素材库创建与扫描 API；真实用户媒体的完整 GUI 交互仍待继续验证，取消目录选择不会创建任何素材库或任务。

- “隐藏”是本地搜索偏好，当前只作用于搜索页结果；素材库、收藏、选片和导出仍会显示对应素材，用户可在搜索页一键恢复全部隐藏项。

- 前端开发构建可用；release 桌面 EXE 已完成启动验证。`core_smoke` 已覆盖中文/空格路径、1,000 文件首次与增量扫描和 SQLite 持久化；搜索页、任务中心与自定义 Selects 导出/排序/推荐时间已有模拟 IPC 的 jsdom 交互测试；NSIS 安装器已完成专用临时目录的静默安装与启动 smoke。
- 默认安装包使用已有 FFmpeg，缺失时视频元数据和缩略图会降级。自行打包可按 [打包说明](./PACKAGING.md) 配置应用同级媒体工具。
- 镜头检测当前使用 FFmpeg 场景阈值，并在视频扫描时自动生成代表关键帧、最长 6 秒短预览，以及黑帧比例和相邻像素细节估算的基础质量。搜索页可显示并聚焦结构化条件命中的镜头，但这一 GUI 交互尚未完成端到端真实媒体验证。黑帧比例 ≥ 85% 和模糊分 ≥ 80% 会作为可搜索的代表帧提示；纯色、低纹理或特殊画面可能被误判为模糊，不能替代多帧质量检测。双下角同时出现小面积高对比元素会产生保守 HUD 提示；它不识别通用 UI、菜单或战斗状态，真实游戏素材的准确率尚未评估。代表关键帧下部的亮暗像素分布还会产生保守字幕提示；它不读取文字、不能替代 OCR，真实字幕样式的准确率尚未评估。尚未提供 PySceneDetect 的高级自适应检测、多帧质量筛选或原视频片段播放。FFmpeg 缺失或单个派生步骤失败时保留完整视频片段但没有派生媒体和质量指标。
- 已接入无需下载模型的本地颜色直方图特征，用于已索引图片和用户明确选择的外部参考图之间的“相似”召回；它不能理解中文自然语言、人物或场景语义。
- 可选本地 CLIP ViT-B/32 图文 Provider 已接入：官方 ONNX Runtime Windows x64 CPU DLL 随应用资源分发，模型仍仅在用户点击设置页“下载模型”后联网写入应用数据目录。它不会依赖开发机 Python；模型标记或任一配对缓存文件缺失时会显式降级，不会在扫描或搜索时隐式下载。当前模型的中文语义质量尚未在真实素材集验证，不能视为中文视觉文本模型。
- CLIP 搜索仅对一组明确列出的中文创作/ACG 词（如角色、雨夜、侧脸、回头、战斗、常见景别/视角、动作、情绪和发色）做本地英文提示扩展；Must Not 词不会进入提示。未知中文专有名词与任意句子会保留关键词降级，尚不具备通用中文、日文语义理解。
- 基础自然语言视觉降级仅覆盖红、绿、蓝、黄和夜色等颜色词；对于“人物回头”“城市远景”等通用描述，当前仍只回退到文件名/路径关键词，结果页会如实展示这一限制。
- 视频视觉特征依赖 FFmpeg 成功生成封面；当前开发机已用合成 MP4 验证代表帧索引，真实用户视频素材仍待验证。
- 当前搜索具备本地文件名/路径关键词匹配、颜色词降级召回与参考图相似检索；安装并重建后可使用 CLIP 级图文向量召回。尚不具备经验证的通用中文自然语言视觉语义理解。
- 当前关键词与 CLIP 候选采取去重补充，不是已校准的统一分数融合；CLIP 候选会严格遵守媒体类型、最低质量与 Must Not，但语义层面对 Must 条件、结果多样性和跨路重排仍待完善。
- Must / Must Not 当前过滤文件名、路径、用户确认的 ACG 标签和已生成视频片段的字幕、黑帧与模糊提示；多个结构化片段条件会在同一个镜头上组合，避免跨镜头误命中。Should 已参与软排序，结果会显示实际命中原因和未满足的 Should，ACG 标签命中不会被误报为文件名命中。关键词、CLIP 与 Entity 候选已在合并后稳定排序；同分候选按素材库轮换以保留基础多样性，但尚未进行跨 Provider 分数校准或镜头级多样性重排。Must Not 的已排除候选原因和 UI 自动过滤仍未完成。
- 可创建自定义选片集合，并支持移动、移除、评分、备注、推荐入/出点和拖拽排序；视频镜头可加入“我的选片”或任一自定义集合并显示其片段范围。默认和自定义集合均可导出 CSV/JSON/EDL/FCPXML，导出会优先采用推荐入/出点、其次采用片段范围。FCPXML 会规范编码 Windows 文件 URI、使用互不冲突的格式/素材资源 ID，并保留可用的视频源帧率和分辨率；其时间线帧率采用首个有效素材帧率。CMX 3600 EDL 仍固定为 30fps 非丢帧，且两种格式均未处理轨道、转场或速度变化，也尚未在剪辑软件内完成导入验证。
- Entity 支持名称/别名在自然语言请求中的本地匹配及多张正/负本地参考图；正样本可按颜色或（已安装并重建时）CLIP Provider 检索相似素材，负样本以保守权重参与排序惩罚，误加参考图可按实体归属安全移除。候选“是/非”反馈会立刻触发本地重新检索；结果目前仍是去重合并而非跨 Provider 校准的统一置信度，实体置信度、通用中文语义效果评估和完整 ACG Creator Pack 尚未完成。
- ACG Creator Pack 的用户确认标签可参与组合搜索；当前仅为简短 `UI` / `HUD` 条件提供保守双下角 HUD 提示，中文“游戏 UI”仍由用户确认标签处理。自动战斗状态、表情、视角及通用游戏 UI/菜单识别仍待视觉模型能力完成。
- 当前 release EXE 已构建并实际启动验证。NSIS 打包会由 `build.rs` 从锁定的 Cargo WebView2 依赖暂存并显式携带 `WebView2Loader.dll`；版本控制的 SVG 图标源会生成 Windows ICO。2026-07-26 已用当前带新图标的 NSIS 安装器完成隔离目录静默安装（退出码 0）与 8 秒启动 smoke，并确认 ONNX Runtime 同级分发。该检查没有下载或使用 Edge。尚未在干净 Windows 环境完成交互式安装、卸载、升级和 MSI 验证。

## 开发环境限制

- 使用 MinGW-w64 而非 MSVC，可能存在个别 Windows 原生 API 兼容问题。
- GNU 构建的库测试已补齐 Windows Common Controls 清单。运行测试需要把 MinGW-w64 的 `gcc`、`windres` 和 `ar` 加入 PATH。
- 真实桌面 E2E 已覆盖 debug 应用的启动、首页壳层、隔离临时 PNG 素材库的真实扫描任务和详情资产回读、中文/空格且超过 260 字符路径的图片缩略图、损坏 PNG 不阻断扫描、200 个隔离 PNG 扫描任务从页面暂停/恢复后全部入库、强制结束应用后以同一 SQLite 自动恢复并完成 1,000 PNG 扫描、无 API Key 的本地关键词搜索结果及其 Must 命中原因、隔离 SQLite 中自定义 Selects 集合的创建/刷新持久化、隔离视频片段加入自定义集合后的 Selects 回读，以及从该集合触发真实 CSV 写出并校验片段入点。显式提供本机 FFmpeg 路径时，E2E 也已实测隔离 MP4 的扫描、视频时长与镜头片段写入；真实用户视频和不同时长/编码组合仍待验证。E2E 使用应用内嵌 WebDriver，测试数据目录只由测试 feature 的 `SCENEWEAVER_E2E_DATA_DIR` 接管，不会下载或管理 Edge/Chrome Driver，且测试 feature/夹具不进入 release/NSIS 安装包。
- 同一 E2E 已在真实实体页面创建带别名的隔离 Entity，并从搜索页以该实体召回已扫描素材、校验实体匹配解释；正/负参考图选择、视觉召回和真实用户实体仍待进一步验证。
- 同一隔离桌面 E2E 已通过真实“参考图”按钮，验证本地颜色特征可从用户指定的参考 PNG 召回不同颜色的已索引素材；系统文件选择器本身、Entity 正/负参考图交互和真实用户媒体仍待进一步验证。
- 同一 E2E 已在真实实体页验证一张正参考和一张负参考的添加、SQLite 持久化、实体结果区域渲染与颜色特征排序惩罚；系统文件选择器本身、更多参考图组合、语义 Provider 与真实用户实体仍待进一步验证。
- release EXE 已实际验证不开放 E2E WebDriver 端口，NSIS 安装 smoke 已确认 `WebView2Loader.dll` 与 `onnxruntime.dll` 被部署；但干净机器上的首次安装、卸载、升级和完整工作流仍待验证。
- 早先 `tauri-driver` 的安装失败是启动 shell 未把 `C:\msys64\mingw64\bin` 放入 PATH，而不是缺少 `ktmw32` 库；该 external 路径现不作为项目 E2E 依赖。
- 使用 GNU 工具链时，需要将 `C:\msys64\mingw64\bin` 加入启动 Cargo 的当前 shell `PATH`，以提供 `gcc` 与 `windres`。
- Windows release EXE 与当前代码生成的 NSIS 安装包均已验证；MSI、干净环境的交互式安装、卸载和升级仍待验证。
- 已配置 GitHub Actions Windows 质量门禁。首次远端运行暴露并推动修复了干净工作目录的 `WebView2Loader.dll` 资源缺陷；2026-07-19 的修复复验已通过 Rust 编译和默认 core smoke。它默认不下载语义模型，也不安装 FFmpeg，因此不会替代本地的模型、视频派生或安装器 smoke。
- 镜头检测和关键帧/短预览派生在 90 秒超时后会终止并回收 FFmpeg 子进程；ffprobe 元数据读取也会在 30 秒超时后终止并回收。`core_smoke` 已直接覆盖本地慢进程的超时回收，但尚未以真实损坏媒体复现 30 秒超时。任务暂停仍会等待正在执行的单个外部媒体步骤完成或超时。

## 待验证项

- 真实用户视频与更多损坏媒体格式扫描；中文、空格、超过 260 字符路径的图片扫描、1,000 文件首次/增量扫描及单个损坏 PNG 不阻断扫描已由 `core_smoke` 实测通过。
- 外接硬盘离线恢复。
- 应用强制结束后的扫描恢复 GUI 已由隔离桌面 E2E 验证；恢复会重新执行安全的增量扫描，尚非媒体处理级精确断点续跑。
- 无 API Key 的关键词、基础参考图相似检索、Entity 别名以及一正一负颜色参考图 GUI 已由隔离桌面 E2E 验证；系统文件选择器、更多 Entity 视觉参考组合和真实用户媒体的完整交互仍待验证。
- 自定义集合的片段推荐入/出点已由隔离桌面 E2E 经真实 UI 验证为可写入 CSV/JSON/EDL/FCPXML；EDL 固定 30fps 非丢帧，四种格式尚未在 DaVinci Resolve、Premiere Pro 或 Final Cut Pro 中以真实媒体实际导入。
- 自定义集合的上下按钮排序已由隔离桌面 E2E 验证其 SQLite 写回和 JSON 导出顺序；原生拖拽手势、更多项目规模和专业软件实际导入仍待验证。
- 2026-07-28 已用本机已有 FFmpeg 运行完整隔离桌面 E2E，确认临时 MP4 的真实扫描、视频时长和镜头片段写入；本机未发现 DaVinci Resolve 或 Adobe Premiere Pro，故尚未在专业软件中以真实媒体导入 EDL/FCPXML。
- 同一视频 E2E 已验证关键帧、短预览及基础质量分数实际写入并可从缓存读取；真实用户视频、更多编码组合和专业软件导入仍待验证。
